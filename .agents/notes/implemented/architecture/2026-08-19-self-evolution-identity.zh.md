# Agent Note: 自进化身份不依赖模型路由

Status: implemented

[English](2026-08-19-self-evolution-identity.md) | 中文

## 问题

实验性进化 Agent 组合曾把供应商和早期启动阶段混入目录、会话、终端和文档身份。这两项运行细节都不能指代该示例在更换模型和重启后仍保留的能力。

只改可见标题会让旧概念继续留在持久会话 id、运行资产名称、运维命令、提示词和 Agent 自己维护的文档中。模型从回放历史和当前组合里仍会读到互相冲突的身份。

## 决策

示例位于 `examples/self-evolution`，稳定根会话是 `self-evolution-main`，运维使用的 rmux 会话是 `self-evolution`。提示词和文档把自进化定义为一个重复闭环：观察当前行为，做一次可恢复的小步修改，验证可观察行为，持久化成功变化，然后再次观察。

模型路由保持为普通配置。当前独立组合仍在选择 LLM 供应商和模型的位置写明 `kimi-coding` 与 `k3-256k`，但两者都不是 Agent 身份。更换供应商不需要再改示例、会话或操作说明的名字。

[自进化 Web 运行时](2026-08-19-self-evolution-web-runtime.md)把浏览器传输直接挂进同一份独立组合。它复用稳定 Agent，不通过内置预设或用户预设复制身份。

## 曾考虑的替代方案

**保留供应商相关的启动身份，只增加自进化显示名。** 否决，因为路径、会话 id、终端标签、回放提示词和持久化文件名仍会传递旧身份。

**移除所有 Kimi 引用。** 否决，因为 `kimi-coding`、`k3-256k` 和 `KIMI_API_KEY` 是准确的供应商配置。隐藏它们不会让 Agent 更独立，只会增加组合的运维难度。

**用内置预设或用户预设表示 Web 运行时。** 否决，因为预设会组装另一个 Agent，而不是暴露持有实验状态的活动独立运行时。

## 结果

该身份不随供应商变化，并准确描述用户选择的行为。仓库路径、根会话、rmux 会话、终端入口和浏览器入口使用同一个名字。已有会话日志和持久化动态插件文件随稳定会话 id 一起迁移，积累的进化历史仍可使用。

终端入口和浏览器入口访问同一进程里的同一个 Agent，因此共享实时 IPython 状态、动态插件和会话历史。独立示例的持久化插件会等待匹配的 `agent/created` 事件，再回放激活中的动态插件，因此组合加载顺序不会在重启时丢掉已持久化的行为。回放失败时保留激活标记以供后续重试，不会把暂时的运行时或代码错误变成永久退休。示例根目录下的插件纳入 host TypeScript 程序，使可运行组合及其回归测试使用同一个编译面。
